3 สถานการณ์หลัก

วิธีใช้

ทุกสถานการณ์เริ่มด้วยการพิมพ์ประโยคธรรมดา — ไม่ต้องจำคำสั่ง

1

มีโปรเจคอยู่แล้ว อยากให้เข้ามาตรฐาน

ทำให้โปรเจคนี้ deploy ได้ตามมาตรฐานบริษัทหน่อย

Claude จะตรวจของเดิมก่อนเสมอ (มีอะไรอยู่แล้วจะถาม ไม่ทับเงียบ ๆ) → ถามคำถามชุดเดียว → ไล่ติดตั้งตามลำดับ → รันสคริปต์ตรวจจนเขียวทุกตัว → ได้ ไฟล์ docs/admin-handoff.md ส่งต่อทีม admin/DevOps ได้ทันที — ขั้นตอนชัดเจน ชื่อที่ต้องตั้งเป๊ะ ๆ พร้อมช่องกรอกค่าตอบกลับ

Database→Quality→Design→Auth→CI
2

โปรเจคใหม่ มีแต่โฟลเดอร์ requirement

อ่าน requirement แล้วทำ brief แยกเป็น feature
  1. อ่านก่อน อย่าเพิ่งสร้าง — ประโยคข้างบนจะได้เอกสารสรุปภาษาไทย + รายการคำถามที่ต้องถาม stakeholder ก่อนเขียนโค้ดผิดทิศ
  2. ติดตั้งมาตรฐานด้วย /ugt-nextjs-full-setup (ตอบคำถามโดยใช้ข้อมูลจาก brief) — ตัวช่วยดีไซน์จะสร้างโปรเจค Next.js ให้เองถ้ายังไม่มี
  3. วนสร้างทีละ feature: "สร้างหน้า X ตาม requirement ใน docs/Y" — ระบบคุมคุณภาพประกบเองอัตโนมัติ
  4. จบวัน: /ugt-handoff แล้ว commit — พรุ่งนี้ (หรือเพื่อน) เปิดมาอ่านต่อได้ทันที
3

อยากจัดดีไซน์อย่างเดียว

ทำข้อตกลง design ให้โปรเจคนี้หน่อย

Claude ถามไม่กี่ข้อ (สีหลักของแบรนด์? มีโหมดมืดไหม? เมนูข้างหรือบน?) — ตอบ "ตามมาตรฐานทั้งหมด" ก็ได้ — แล้วได้:

  • docs/DESIGN.md — ข้อตกลงดีไซน์ของโปรเจค เขียนทุกการตัดสินใจพร้อมวันที่
  • ธีมสี + ฟ้อนต์ไทย + โครงเมนู ตามมาตรฐานองค์กร (ตรวจ contrast สำหรับผู้มีปัญหาการมองเห็นแล้วทุกคู่สี)
  • ชุด component สำเร็จรูป: ตารางข้อมูลครบเครื่อง (ค้นหา กรอง เรียง จำการตั้งค่า), ฟอร์ม, ป้ายสถานะ, ปุ่มยืนยันลบ ฯลฯ
  • กฎที่ทำให้ Claude อ่านข้อตกลงเองทุกครั้งก่อนแตะงาน UI — session หน้าก็ยังรักษาดีไซน์เดิม

โปรเจคเดิมที่มี UI แล้ว: สแกนของจริงก่อน แล้วชวนตกลงว่าจุดไหนปรับตาม จุดไหนคงไว้ (บันทึกเป็นลายลักษณ์อักษร ไม่ไล่แก้ทั้งแอปเงียบ ๆ)

หลังติดตั้งแล้ว
