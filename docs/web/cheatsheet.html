ทำ feature — bundle superpowers (เดินเอง)

อ่าน project-context→คิดก่อน→วางแผน→เขียนเทสต์ก่อน→review
  • เริ่มจาก requirement: /ugt-requirements → "สร้าง feature X ตาม docs/requirements-brief/NN.md"
  • งานเล็ก (ไม่กำกวม · ~1–3 ไฟล์ · ไม่ใช่ auth/เงิน/concurrency) → light version: ข้ามคิด-วางแผน แต่ยังเขียนเทสต์ + review · ตอบ "full" ถ้าอยากได้เต็ม
  • 1 feature = 1 session ใหม่

ห้ามแก้ไฟล์ตัวช่วยที่ติดตั้งมา (หายตอน update) · ห้ามสร้างตัวช่วยชื่อ ugt-* ซ้ำของเดิม

ห้ามพลาด — กติกาที่ทำ build/ข้อมูลพัง

  • งานตั้งเวลา = host cron เท่านั้น — ห้าม node-cron / setInterval / SQL Agent job / Jenkins timer · cron เรียก /api/cron/<job> พร้อม CRON_SECRET
  • ลบข้อมูล = IsDeleted = 1 (soft delete) ห้าม hard delete
  • ตารางใหม่มี audit columns ครบ: Id CreatedAt UpdatedAt CreatedBy UpdatedBy IsActive IsDeleted · ชื่อตาราง PascalCase พหูพจน์
  • ห้ามใช้ reserved word เป็นชื่อคอลัมน์ (key value group count order) — เติมคำขยาย
  • แก้ schema.prisma → npx prisma migrate dev แล้ว npx prisma generate ทุกครั้ง
  • Server Action สิทธิ์สูง: session → permission → action → audit log
  • ห้ามอ่าน process.env ตรง → import { env } from '@/lib/env'
  • ห้าม $queryRawUnsafe กับ input ผู้ใช้ — ใช้ tagged template
  • ไฟล์ที่ต้องรอดหลัง deploy → bind mount ใต้ /home/docker02/appdata/<project>/ ห้าม named volume
  • Quality Gate (โค้ดใหม่): violations = 0 · coverage ≥ 60% · ซ้ำ ≤ 3%
