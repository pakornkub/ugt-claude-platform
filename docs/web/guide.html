1ก่อนเริ่ม

เตรียม 3 อย่างนี้ให้พร้อม แล้วทุกขั้นถัดไปจะลื่น

  1. Claude Code

    ทุกคำสั่งและทุกประโยคในคู่มือนี้พิมพ์ในช่องแชทของ Claude Code

    รีโปของ platform เป็น public จึงไม่ต้องขอสิทธิ์หรือ login GitHub

  2. โปรเจค Next.js แบบ App Router

    ชุดนี้ทำมาเพื่อ TypeScript / React / Next.js (App Router) · SQL Server · Keycloak · Jenkins + SonarQube + Docker

    ยังไม่มีโปรเจคเลยก็ได้ ตัวช่วยดีไซน์จะสร้างโปรเจค Next.js ให้เอง

  3. ข้อมูลที่จะถูกถาม

    ตอนติดตั้ง Claude จะถามคำถามชุดเดียว เตรียมคำตอบเหล่านี้ไว้ก่อน:

    เรื่องตัวอย่างสิ่งที่ถูกถาม
    ตัวตนโปรเจคชื่อแบบ kebab-case (เช่น expense-portal) + ชื่อที่แสดง · basePath · port prod/dev · URL เต็มของ prod/dev
    ฐานข้อมูลDB server · ชื่อ database · ของเดิมหรือสร้างใหม่ · ต้องใช้ stored procedure ไหม
    LoginSSO / AD (LDAP) / รหัสผ่าน · มี Keycloak client แล้วหรือยัง · ข้อมูล AD · โดเมนอีเมลองค์กร · view ข้อมูลพนักงาน
    CI/CDใช้ Sentry ไหม · deploy ไปที่ไหน
    ตัวเลือกเสริมต้องส่งอีเมลแจ้งเตือนไหม (ถ้าใช่ ขอ SMTP host/port, อีเมลผู้ส่ง) · ผู้ใช้ต้องแนบไฟล์ไหม (ถ้าใช่ ขนาดไฟล์สูงสุด)
    ไม่รู้คำตอบบางข้อ ไม่เป็นไร ข้อที่ไม่ได้ตอบ Claude จะใช้ค่ามาตรฐาน แล้วบอกให้รู้ตอนปิดงาน ส่วนค่าที่ต้องขอจาก admin (รหัสผ่าน DB, Keycloak secret) จะรวมไว้ในไฟล์ให้ส่งต่อทีหลัง
ผลที่ควรเห็น มี Claude Code พร้อมใช้ มีโฟลเดอร์โปรเจค (หรือโฟลเดอร์ว่าง) และรู้คร่าว ๆ ว่าจะตอบคำถามข้างบนว่าอะไร
ไม่ใช่ Next.js? Claude จะบอกตรง ๆ ว่าใช้ไม่ได้ และจะไม่ดัดแปลงไฟล์ให้เข้ากับ stack อื่นเอง · Python / PHP มีเฉพาะส่วน deploy (ดูบทที่ 9)
อ่านละเอียด → คำถามทั้งหมดของ full-setup

2ติดตั้ง

ทำครั้งเดียวต่อเครื่อง (หรือต่อโปรเจค ถ้าเลือก scope project)

  1. เลือก bundle

    bundle = plugin ตัวเดียวที่ติดแล้วได้ของครบชุด ต่างกันแค่ "วิธีทำ feature"

    Bundleเหมาะกับ
    ugt-nextjs-standard-superpowers แนะนำไม่แน่ใจให้เลือกตัวนี้ ระบบเดินเองอัตโนมัติ: คิดก่อน → วางแผน → เขียนเทสต์ก่อน → review
    ugt-nextjs-standard-mattpocockอยากคุมทุกขั้นเอง และประหยัด token กว่า แต่ต้องเรียกคำสั่งเองทีละขั้น และไม่มีอะไร review ให้อัตโนมัติ

    ทั้งสองตัวพา ugt-nextjs-platform และ ugt-core มาให้เอง ไม่ต้องติดแยก

  2. รันคำสั่งทีละบรรทัด

    เปิด Claude Code ในโปรเจคไหนก็ได้ แล้วพิมพ์:

    /plugin marketplace add pakornkub/ugt-claude-platform
/plugin install ugt-nextjs-standard-superpowers@ugt
/reload-plugins
# เลือก mattpocock: บรรทัดที่สองใช้ ugt-nextjs-standard-mattpocock@ugt แทน

  3. เลือก scope ตอน install

    Scopeผล
    projectเพื่อนร่วมทีมที่ clone โปรเจคไปได้ด้วย
    userใช้เองได้ทุกโปรเจคในเครื่องนี้

  4. เช็คว่าติดแล้ว

    /ugt

    ต้องเห็นรายการตัวช่วยที่ขึ้นต้นด้วย ugt- เด้งขึ้นมา

ผลที่ควรเห็น พิมพ์ /ugt แล้วเห็นตัวช่วยอย่าง ugt-nextjs-full-setup, ugt-handoff, ugt-requirements · ดูรุ่นที่ติดอยู่ได้ด้วย /plugin
เปลี่ยน bundle ทีหลังได้ แต่ต้อง uninstall ตัวเดิมแล้ว install อีกตัวเอง ไม่มีคำสั่งสลับให้
อ่านละเอียด → เทียบสอง bundle

3ทำโปรเจคที่มีอยู่ให้ deploy ได้

ใช้ ugt-nextjs-full-setup ตัวแม่ ถามครั้งเดียว แล้วติดตั้งทุกอย่างตามลำดับที่ถูก

Claude Code · โปรเจค expense-portal
คุณทำให้โปรเจคนี้ deploy ได้ตามมาตรฐานบริษัทหน่อย
Claudeตรวจโปรเจคแล้ว พบหน้าจอที่ใช้งานอยู่, ข้อมูลเก็บใน SQLite และ login จำลอง · ขอถามคำถามชุดเดียว:
  1. ของเดิมที่ใช้งานอยู่ คงไว้ไหม? (ค่าเริ่มต้น: คงของเดิม)
  2. ติดตั้งอะไรบ้าง? (ค่าเริ่มต้น: ทั้ง 5 อย่าง)
  3. ต้องส่งอีเมลแจ้งเตือนไหม …
คุณคงของเดิม ติดทั้งหมด ไม่ส่งเมล ไม่แนบไฟล์ login ด้วย SSO …
Claudeแผน: Database → Quality → Design → Auth → CI รันรวดเดียวใน session นี้ — พิมพ์ "ลุย" เพื่อเริ่ม

  1. เปิด Claude Code ที่โฟลเดอร์โปรเจค แล้วพิมพ์ประโยคเดียว

    ทำให้โปรเจคนี้ deploy ได้ตามมาตรฐานบริษัทหน่อย

    หรือเรียกตรง ๆ ด้วย /ugt-nextjs-full-setup

  2. Claude ตรวจของเดิมก่อนเสมอ

    มันจะรายงานสิ่งที่เจอก่อนถาม เช่น หน้าจอที่ใช้งานอยู่, ที่เก็บข้อมูลชั่วคราว (SQLite, ไฟล์ JSON), login จำลอง

    อะไรที่มีอยู่แล้วจะถามก่อน ไม่ทับเงียบ ๆ

  3. ตอบคำถามชุดเดียว

    ถามรวดเดียวจบ ตัวช่วยย่อยจะไม่ถามซ้ำ ค่าเริ่มต้นที่ควรรู้:

    คำถามค่าเริ่มต้น
    คงของเดิมที่ใช้งานอยู่ไหม (preserve mode)คงของเดิม: flow, route, หน้าตา และเมนูเดิมอยู่ครบ
    ย้ายข้อมูลจากที่เก็บชั่วคราวไป SQL Server เลยไหมย้าย
    ถอด login จำลอง ใส่ login จริงไหมถอด (เก็บไว้คู่กันไม่ได้)
    ติดตั้งอะไรบ้างทั้ง 5: Database / Quality / Design / Auth / CI
    ส่งอีเมล / แนบไฟล์ไม่ (ทั้งคู่ต้องขอโครงสร้างจาก admin เพิ่ม)
    วิธี loginSSO อย่างเดียว
    ไม่ถามว่าใครเป็น admin คนแรก ไม่มีบัญชี admin สร้างไว้ล่วงหน้า คนแรกที่ login จะถูกพาไปหน้า /admin/setup แล้วกดปุ่มเดียวเป็น Administrator

  4. ดูแผน แล้วยืนยันครั้งเดียว

    Claude เสนอลำดับและวิธีรันมาหนึ่งแบบ ปกติคือรันรวดเดียวใน session นี้

    ลุย

    ถ้าอยาก review ทีละ module ก่อนไปต่อ ให้บอกตอนนี้ Claude จะแบ่งเป็นช่วงละ 1–3 module คั่นด้วย /ugt-handoff

  5. Claude ติดตั้งตามลำดับนี้ (สลับไม่ได้)

    ขั้นตัวช่วยได้อะไร
    Databaseugt-nextjs-database-setupSQL Server ผ่าน Prisma + ตั้งชื่อตาราง/คอลัมน์ตามมาตรฐาน
    Qualityugt-nextjs-test-lint-setupVitest + ESLint + Prettier + ตรวจก่อน commit
    Designugt-nextjs-design-setupdocs/DESIGN.md + ธีม ฟ้อนต์ไทย เมนู + ชุด component สำเร็จรูป
    Authugt-nextjs-auth-setuplogin (SSO / AD / รหัสผ่าน) + สิทธิ์ + หน้า admin
    Mail เลือกได้ugt-nextjs-mail-setupส่งเมลผ่าน relay บริษัท + template แก้ได้จากหน้า admin
    Upload เลือกได้ugt-nextjs-upload-setupแนบไฟล์บน volume + สแกนไวรัส (เปิดได้) + ดาวน์โหลดผ่านการตรวจสิทธิ์
    CIugt-nextjs-cicd-setupJenkinsfile + SonarQube + Docker + /api/health + docs/admin-handoff.md

    ทำไมต้องเรียงแบบนี้: Auth เก็บ user ในฐานข้อมูล · หน้า login ต้องใช้ธีมจาก Design · CI เรียก script ทดสอบที่ Quality สร้าง

  6. Claude วางไฟล์ "ความจำ" ของโปรเจค

    ขั้นนี้ทำเสมอ ไม่ว่าเลือกติดตั้งอะไร เพื่อให้มาตรฐานอยู่ต่อหลังจบ session

    your-project/ ├─ CLAUDE.md # เพิ่มบล็อก ugt:start … ugt:end (ของเดิมไม่แตะ) ├─ .claude/ │ ├─ settings.json # รวมเฉพาะ key ของ plugin │ ├─ rules/ # กฎแต่ละเรื่อง โหลดเองตามไฟล์ที่แตะ │ └─ state/ │ ├─ handoff.md # งานค้าง / คิวถัดไป │ └─ model-mode.md # เริ่มที่ auto ├─ docs/ │ ├─ DESIGN.md # ข้อตกลงดีไซน์ │ ├─ admin-handoff.md # ส่งให้ admin/DevOps │ └─ project-context/ # สารบัญความรู้ของโปรเจค └─ CODING_STANDARDS.md # เฉพาะ bundle mattpocock

  7. Claude รันสคริปต์ตรวจจนเขียวทุกตัว

    ทุก module มี verify.mjs ของตัวเอง รวมถึงของ full-setup ด้วย ข้อไหนแดง Claude ต้องแก้ก่อนบอกว่าเสร็จ

ข้อความปิดงาน — มี 6 หัวข้อเสมอ

#หัวข้อคุณต้องทำอะไรกับมัน
1ไฟล์ที่เพิ่ม/แก้ (แยกตาม module)ไล่ดู diff ก่อน commit
2env vars ที่ต้องเติมค่าจริงเติมใน .env.local เมื่อได้ค่าจาก admin
3ส่งต่อ admin (docs/admin-handoff.md)ส่งไฟล์นี้ให้ทีม admin/DevOps
4ผู้ดูแลคนแรกให้คนที่ควรเป็น admin login คนแรก
5Smoke testทดสอบตามรายการ
6ยังไม่ได้รันรันคำสั่งที่ Claude รันเองไม่ได้

หลัง Claude ทำเสร็จ — งานของคุณ

  1. รันคำสั่งที่ "ยังไม่ได้รัน"

    เช่น บรรทัด npm i …, npx shadcn@latest add …, prisma migrate / generate, npx husky init ถ้า session รันเองไม่ได้

  2. ส่ง docs/admin-handoff.md ให้ admin

    ในไฟล์มีขั้นตอนรวมและตารางแยกระบบ: SQL Server, folder บน server, Jenkins, GitHub webhook, SonarQube, Keycloak, Nginx, cron (มีเฉพาะที่โปรเจคใช้)

    ท้ายไฟล์มีตาราง "ส่งกลับ" ให้ admin กรอก รหัสผ่านและ secret ให้ส่งทางช่องทางปลอดภัย ไม่กรอกในไฟล์

  3. เติมค่า env

    ได้ค่ากลับจาก admin แล้ว เติมลง .env.local ตามรายการในหัวข้อที่ 2

  4. ผู้ดูแลคนแรก

    ให้คนที่ควรเป็น admin login คนแรก ระบบพาไป /admin/setup → กดปุ่มเดียว → ได้ role Administrator

    โปรเจคที่ใช้รหัสผ่านอย่างเดียว (ไม่มี SSO/AD) ต้องสร้างบัญชีแรกด้วย npx tsx scripts/create-first-user.ts ก่อน แล้วค่อยเข้า /admin/setup

  5. Smoke test

    • npm run build ผ่าน
    • login ได้ทุกวิธีที่เปิด → เข้าหน้าที่ต้อง login ได้ → logout แล้ว cookie หาย
    • /admin/setup กดครั้งเดียวได้ Administrator
    • push branch develop → pipeline เขียวทุก stage

  6. bundle mattpocock เท่านั้น

    /setup-matt-pocock-skills

    ต้องรันเอง ครั้งเดียวต่อโปรเจค (full-setup รันแทนไม่ได้)

หลัง push: จาก GitHub ถึงหน้าแอป

pipeline ที่ cicd-setup ติดตั้งให้ทำงานแบบนี้ทุกครั้งที่ push

ผลที่ควรเห็น มี docs/admin-handoff.md ที่ไม่มี __…__ ค้าง · verify.mjs ทุกตัวผ่าน · npm run build ผ่าน · หน้าเดิมยังทำงานเหมือนเดิมแต่อ่านข้อมูลจาก SQL Server จริง
Login ด้วยรหัสผ่าน + ส่งเมล ปุ่ม "ลืมรหัสผ่าน" ต้องรอให้ Mail ติดตั้งเสร็จก่อน Claude จะย้อนกลับไปต่อให้เอง ถ้ายังไม่มี Mail ทางกู้รหัสผ่านมีทางเดียวคือให้ admin ตั้งให้
อ่านละเอียด → ugt-nextjs-full-setup

4เริ่มจาก requirement

โปรเจคใหม่ที่มีแต่กองเอกสาร: อ่านให้ครบก่อน อย่าเพิ่งสร้าง

  1. วางเอกสารไว้ที่ docs/requirements/

    ถ้าไม่มีโฟลเดอร์นี้ Claude จะถามว่าเอกสารอยู่ที่ไหน

    ไฟล์ที่อ่านไม่ได้ (เช่น .docx, spreadsheet) จะถูกระบุว่า unread ให้เห็นชัด ไม่ถูกข้ามเงียบ ๆ

  2. สั่งให้อ่านแล้วทำ brief

    อ่าน requirement แล้วทำ brief แยกเป็น feature

    หรือเรียก /ugt-requirements

    docs/requirements-brief/ ├─ 00-overview.md # ระบบทำอะไร · ผู้ใช้ · รายการ feature · คำถามค้าง ├─ 01-<feature>.md # หนึ่งไฟล์ต่อ feature เรียงตามลำดับที่ต้องทำก่อน └─ 02-<feature>.md docs/project-context/board.md # แถวละ feature เริ่มที่ ☐ todo

  3. เอา Open Questions ไปถาม stakeholder

    ส่วนที่สำคัญที่สุดของ brief คือ "สิ่งที่เอกสารไม่ได้บอก" ถามให้ได้คำตอบก่อนเริ่ม feature ที่ติดคำถามนั้น

    สิ่งที่ Claude เดาเองจะมีป้าย (assumption) กำกับ

  4. ติดตั้งมาตรฐาน

    /ugt-nextjs-full-setup

    ตอบคำถามโดยใช้ข้อมูลจาก brief ทำตามบทที่ 3 ได้เลย

  5. สร้างทีละ feature — feature ละ session ใหม่

    สร้าง feature <ชื่อ> ตาม docs/requirements-brief/<file>

    Claude เสนอแผน build ให้เคาะครั้งเดียว: feature อิสระแยกทำขนานได้ (session + git worktree ละตัว) · feature ที่แชร์ตารางเดียวกันทำเรียงลำดับ

7อัปเดต plugin

เมื่อมีประกาศรุ่นใหม่: อัปเดตความรู้ก่อน แล้วค่อยตามไฟล์ที่ copy ไว้ในโปรเจค

  1. อัปเดต plugin

    /plugin marketplace update ugt
/plugin update ugt-nextjs-standard-superpowers
/reload-plugins
# ติด mattpocock: ใช้ ugt-nextjs-standard-mattpocock ในบรรทัดที่สอง

  2. ตามไฟล์ kit ให้ทัน

    kit = ชุดไฟล์สำเร็จรูปที่ plugin copy เข้าโปรเจค (ตาราง ฟอร์ม หน้า login ฯลฯ) อัปเดต plugin แล้วไฟล์พวกนี้ไม่เปลี่ยนตาม

    sync kit

    ไฟล์ kit ทุกตัวมี "ตราประทับ" 2 บรรทัดบนหัวไฟล์:

    // kit: ugt-nextjs-platform 4.13.0 · ugt-nextjs-design-setup/ui/data-table.tsx
// kit-hash: 5bbf4107cc5f

    เลขรุ่นบอกว่า "ตกรุ่นไหม" · hash บอกว่า "โปรเจคแก้เองไหม" ห้ามแก้สองบรรทัดนี้ด้วยมือ

  3. ดูรายงาน แล้วตอบทีละไฟล์

    สถานะความหมายClaude เสนอ
    ✔ CURRENTตรงกับรุ่นล่าสุดไม่ทำอะไร
    ↑ UPDATEตกรุ่น และโปรเจคไม่เคยแก้ทับด้วยของใหม่
    ⇄ MERGEตกรุ่น และโปรเจคแก้เองรวมสองฝั่ง ของที่โปรเจคแก้ชนะ
    ✘ REMOVEDplugin เลิกแจกไฟล์นี้ดู CHANGELOG (มักเปลี่ยนชื่อหรือเลิกใช้)

    ไม่ตอบ = ไม่เขียน · ตอบ "ทำตามข้อเสนอทั้งหมด" ได้

  4. อ่าน CHANGELOG ของรุ่นที่ข้ามมา

    ถ้ารุ่นไหนต้องทำอะไรเพิ่ม CHANGELOG จะเขียนไว้ชัด (เช่น ข้อ "โปรเจคเดิม" ที่บอกให้ migrate schema หรือ copy ไฟล์ใหม่)

    kit-sync เทียบเฉพาะไฟล์ที่เคย copy ไปแล้ว ไม่เสนอไฟล์ใหม่ ไฟล์ใหม่ต้อง copy ตามที่ CHANGELOG บอก

ผลที่ควรเห็น รัน sync kit ซ้ำแล้วไฟล์ที่เคย UPDATE กลายเป็น CURRENT · ไฟล์ที่ merge ยังขึ้น MERGE (ปกติ) แต่เป็นรุ่นใหม่ · build และเทสต์ผ่าน · มีบันทึกมติว่าอัปเดตไฟล์ไหนจากรุ่นไหน
สีหรือ DESIGN.md ไม่ตรงรุ่น? นั่นไม่ใช่งานของ kit-sync ให้พิมพ์ "sync ข้อตกลง design" แทน · CHANGELOG บอกว่าแก้บั๊กแล้วแต่ยังเจอ = ไฟล์ในโปรเจคน่าจะเก่า ให้ sync kit
ยังติด ugt-nextjs-standard ตัวเดิม (ไม่มีคำต่อท้าย)? /plugin update จะหาไม่เจอแล้ว ให้รัน /plugin install ugt-nextjs-standard-superpowers@ugt เอง
อ่านละเอียด → ugt-nextjs-kit-sync

8เจอบั๊กที่น่าจะเจอทุกโปรเจค

ยกขึ้นเป็น PR เข้า platform ทีมอื่นจะได้ไม่ต้องเจอซ้ำ

Claude Code
คุณอันนี้น่าจะเจอทุกโปรเจค ส่ง PR ไป platform ให้หน่อย
Claudeตรวจ 3 ข้อแล้วผ่านทั้งหมด · เจ้าของคือ ugt-nextjs-pitfalls · นี่คือ diff และข้อความ PR — ยืนยันให้เปิด PR ไหม?
คุณยืนยัน

  1. สั่ง contribute

    /ugt-contribute

    เลือกบั๊กหนึ่งข้อจาก troubleshooting.md หรือบั๊กที่เพิ่งแก้ใน session นี้ · หนึ่งรอบ = หนึ่งเรื่อง = หนึ่ง PR

  2. ผ่านด่าน 3 ข้อ

    • สาเหตุอยู่ที่ stack (Prisma, Keycloak, Jenkins, shadcn…) ไม่ใช่ข้อมูลหรือกติกาของโปรเจคนี้
    • โปรเจคที่สองจะเจอเหมือนกัน ถ้าทำตามตัวช่วยตรง ๆ
    • วิธีแก้พิสูจน์แล้ว (ขึ้น production / เทสต์ผ่าน) ไม่ใช่ "น่าจะ"

    ข้อไหนตอบ "ไม่" ก็จบตรงนั้น เรื่องนั้นอยู่ใน troubleshooting.md ของโปรเจคต่อ

  3. Claude เขียน entry ใน clone ชั่วคราว

    เลือกตัวช่วยเจ้าของเรื่อง เขียน entry (อาการ → สาเหตุ → วิธีแก้ → ที่มา) + บรรทัด CHANGELOG ใต้ ## Unreleased

    ไม่ตั้งเลขรุ่นเอง ผู้ดูแล platform ตั้งตอนออกรุ่น · Claude ใช้ git และ gh (GitHub CLI) ทำขั้นนี้

  4. ดู diff แล้วยืนยัน

    Claude โชว์ diff + ข้อความ PR แล้วรอ ต้องตอบยืนยันก่อนถึงจะ push และเปิด PR

    push ไม่ผ่าน (ไม่ใช่ผู้ดูแล) → ได้ไฟล์ .patch ไปส่งให้ผู้ดูแล platform แทน

  5. ปิดฝั่งโปรเจค

    Claude ลบ entry ออกจาก troubleshooting.md แล้วให้คุณรัน /ugt-handoff เพื่อ commit พร้อมลิงก์ PR

ผลที่ควรเห็น ได้ลิงก์ PR · entry หายจาก troubleshooting.md ของโปรเจค · ทีมอื่นได้ของใหม่ตอน /plugin update หลัง PR ถูก merge และออกรุ่นแล้ว
ห้ามแก้ไฟล์ตัวช่วยที่ติดตั้งมาเอง ไฟล์ใน plugin cache หายตอนอัปเดต และไม่มีใครได้ด้วย · ห้ามสร้างตัวช่วยชื่อ ugt-* ซ้ำของเดิม ถ้าอยากต่อยอดให้ตั้งชื่อใหม่

9ถามบ่อย

คำถามที่ทีมเจอบ่อยตอนเริ่มใช้

ต้องจำชื่อตัวช่วยไหม?

ไม่ต้อง พิมพ์ภาษาไทยธรรมดาได้เลย เช่น "ต่อ database", "ใส่ login SSO", "ทำ CI" Claude เลือกตัวช่วยให้เอง

อยากเรียกตรง ๆ ก็พิมพ์ /ugt แล้วเลือกจากรายการ

อยากทำแค่เรื่องเดียว ต้องผ่าน full-setup ไหม?

ไม่ต้อง ถ้าบอกเรื่องเดียวชัด ๆ เช่น "ทำข้อตกลง design" หรือ "ต่อ database" Claude จะไปที่ตัวช่วยนั้นตรง ๆ

แต่ลำดับยังสำคัญ: Design ต้องมาก่อน Auth · Quality ต้องมาก่อน CI

เลือก bundle ไปแล้ว เปลี่ยนทีหลังได้ไหม?

ได้ uninstall ตัวเดิมแล้ว install อีกตัว (ไม่มีคำสั่งสลับ)

จากนั้นให้ full-setup ทำขั้นวางไฟล์ harness ใหม่ เพื่อสร้างบล็อกใน CLAUDE.md ให้ตรงกับ bundle ใหม่

อยากคงหน้าตาเดิมของโปรเจค จะโดนเปลี่ยนไหม?

ตอบ "คงของเดิม" ตอนถูกถาม (เป็นค่าเริ่มต้นอยู่แล้วถ้ามี UI เดิม) flow, route และเมนูเดิมอยู่ครบ

ตัวช่วยดีไซน์จะสแกนหน้าเดิม วัดสีหลักและขนาดของเดิม (ฟ้อนต์จะถามก่อน ค่าเริ่มต้นคือคงฟ้อนต์เดิม) แล้วปรับชุด component ให้เข้ากัน หน้า admin ใหม่จึงไม่หลุดธีม

Claude บอกว่า "ยังไม่ได้รัน" คืออะไร?

บาง session รันคำสั่งไม่ได้ (ไม่มี shell) Claude จะเขียน package ลง package.json เองตามรุ่นที่กำหนด และเขียนไฟล์ที่ทำแทนได้

คำสั่งที่เหลือ (npm i …, npx shadcn@latest add …, prisma migrate/generate, npx husky init) จะอยู่ในหัวข้อ "ยังไม่ได้รัน" ให้คุณรันเอง ไม่ถูกข้ามเงียบ ๆ

ใครเป็น admin คนแรก? ต้องสร้างบัญชีไว้ก่อนไหม?

ไม่มีบัญชี admin ตั้งไว้ล่วงหน้า คนแรกที่ login จะถูกพาไป /admin/setup กดปุ่มเดียวเป็น Administrator ให้คนที่ควรเป็น admin login คนแรก

โปรเจคที่ใช้รหัสผ่านอย่างเดียว: รัน npx tsx scripts/create-first-user.ts สร้างบัญชีแรกก่อน

กับดักที่เคยพังบน production อ่านได้ที่ไหน?

อยู่ในตัวช่วย ugt-nextjs-pitfalls แยกเป็นเรื่อง: วันที่/timezone · การดึงข้อมูล · ฟอร์ม · hardening · หลัง deploy (version skew)

มันโหลดเองเมื่อแตะไฟล์โค้ด ไม่ต้องเรียก · อ่านสรุปอาการได้ที่ หน้ารายละเอียดตัวช่วย

Python / PHP ใช้ได้หรือยัง?

ได้เฉพาะส่วน deploy (Jenkins + SonarQube + Docker) ผ่าน ugt-python-cicd-setup และ ugt-php-cicd-setup · ยังไม่มี database/auth

ทั้งสองตัวยังไม่ผ่าน pilot ครบและยังไม่ออกรุ่นอย่างเป็นทางการ (ยังไม่ tag)

/ugt-model-mode เปลี่ยน model ของ session หลักได้ไหม?

ไม่ได้ โหมดมีผลกับงานที่ส่งให้ตัวช่วยย่อย (subagent) เท่านั้น · model ของ session หลักเปลี่ยนด้วย /model ซึ่งคุณต้องพิมพ์เอง

เจอ error แปลก ๆ ควรเริ่มตรงไหน?

เปิด docs/project-context/troubleshooting.md ของโปรเจคก่อน เผื่อเคยมีคนเจอแล้ว
