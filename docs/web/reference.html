อ่านหน้านี้ยังไง

  1. ทุกตัวช่วยมีหัวข้อเหมือนกันทุกตัว — ทำอะไร → ใช้เมื่อไหร่ → ต้องมีก่อน → จะถามอะไร → ได้อะไรในโปรเจค → ตัวเลือก → กฎที่ห้ามพลาด → อาการที่เจอบ่อย → ตรวจว่าเสร็จ อ่านตัวแรกครั้งเดียวแล้วตัวอื่นอ่านแบบเดิมได้เลย
  2. เรียกใช้ได้สองทาง — พิมพ์ชื่อคำสั่ง เช่น /ugt-nextjs-auth-setup หรือพิมพ์ประโยคไทยธรรมดา เช่น "ใส่ระบบ login" แล้ว Claude เลือกตัวช่วยให้เอง (ประโยคตัวอย่างอยู่ในหัวข้อ "ใช้เมื่อไหร่")
  3. เจอ error มา — พิมพ์ข้อความ error ลงช่องค้นด้านบน หน้าจะเหลือเฉพาะตัวช่วยที่พูดถึงมัน และเปิดหัวข้ออาการที่ตรงให้
  4. คำที่ใช้บ่อย — kit = ชุดไฟล์สำเร็จรูปที่ plugin copy เข้าโปรเจค · verify.mjs = สคริปต์ตรวจงานที่ติดมากับตัวช่วยแต่ละตัว (✘ = ยังไม่เสร็จ) · preserve mode = โหมด "คงของเดิม" สำหรับโปรเจคที่มีหน้าจอใช้งานอยู่แล้ว · basePath = path ย่อยที่แอปอยู่ใต้โดเมนกลาง เช่น /expense-portal · placeholder = ค่าแบบ __PROJECT_NAME__ ที่ต้องแทนด้วยค่าจริง

5ตัวเลือก / เงื่อนไข

  • Preserve mode (Q0 = คงของเดิม): workflow, route, business logic คงเดิม · หน้าตาคงเดิมแต่ component เปลี่ยนเป็น shadcn ได้ · shell (เมนู/layout) คงเดิม · หน้า admin ใช้ DataTable ของ kit ที่กลืนด้วย token ที่ปรับแล้ว ส่งต่อแบบนี้: design → scan บังคับ · auth → merge เข้าเมนูเดิม + ถอด login จำลอง · database → ย้าย store เดิม
  • รูปแบบการรัน (เสนอครั้งเดียว): ค่าเริ่มต้นคือรันต่อเนื่องใน session เดียว · แบ่งเป็นช่วงละ 1–3 โมดูลแล้วจบแต่ละช่วงด้วย /ugt-handoff เฉพาะเมื่อผู้ใช้อยากตรวจทีละโมดูล · ส่งแต่ละโมดูลให้ subagent เมื่อผู้ใช้ขอ — ทุกแบบรันทีละโมดูลตามลำดับเสมอ
  • Local login + Mail: "ลืมรหัสผ่าน" อยู่ใน auth แต่ส่งผ่าน mail จึงต้องย้อนกลับไปติดตั้งส่วน reset ของ auth (§5.5) หลัง mail เสร็จ
  • Upload: ติดตั้งหลัง Auth แต่ส่วนแก้ compose/Dockerfile รอจน cicd-setup เขียนไฟล์เหล่านั้นแล้วค่อยทำตอนปิดงาน
  • ไม่มี shell (session รันคำสั่งไม่ได้): เพิ่ม package ลง package.json ด้วยมือตามเวอร์ชันบรรทัด npm i (ไม่มีเวอร์ชัน → ^<major ปัจจุบัน> ห้าม "latest") แล้วลิสต์ทุกคำสั่งที่ยังไม่ได้รันไว้ในหัวข้อ "ยังไม่ได้รัน"
  • เลือก bundle อัตโนมัติ: ตรวจว่ามี superpowers หรือ mattpocock-skills ติดตั้งอยู่ — มีทั้งคู่หรือไม่มีเลย จะถามหนึ่งข้อ ตอบ "ไม่ใช้" → "enabledPlugins": {}
  • ระหว่างติดตั้ง ไม่เรียกตัวช่วยจาก superpowers / mattpocock-skills / frontend-design — SKILL.md ของตัวช่วยลูกคือแผน และ verify.mjs คือการ review อยู่แล้ว

6กฎที่ห้ามพลาด

  • ลำดับ Database → Quality → Design → Auth → [Mail] → [Upload] → CI เสมอ — ข้ามตัวที่ไม่เลือกได้ แต่ห้ามสลับ
  • ห้ามทับ Prisma / ระบบ auth / Jenkinsfile ที่มีอยู่แบบเงียบ ๆ — รายงานแล้วถามก่อน
  • "คง design เดิม" ไม่ใช่ "ข้ามขั้น design" — ต้อง scan แล้วปรับ token ของ kit ให้เท่าของเดิม
  • ห้ามรายงานว่า "ต่อ database แล้ว" ทั้งที่หน้าจอยังอ่าน store เดิม
  • แก้ CLAUDE.md เฉพาะใน block ugt:start/end · ห้ามรีเซ็ต .claude/state/ ที่มีอยู่
  • ติดตั้ง harness ทุกครั้ง แม้เลือกโมดูลเดียว
  • ข้อความปิดงานต้องมีครบ 6 ส่วน: ไฟล์ที่เพิ่ม/แก้ · env ที่ต้องเติมค่าจริง · ส่งต่อ admin · ผู้ดูแลคนแรก (/admin/setup) · smoke test · ยังไม่ได้รัน — เขียนในแชทเลย ไม่ใช่แค่ "ดูไฟล์ docs/…"
  • bundle mattpocock: บอกผู้ใช้ให้รัน /setup-matt-pocock-skills เอง (ตัวช่วยรันแทนไม่ได้)

ติดตั้งครบแล้ว แต่ทุกหน้าจอยังใช้ข้อมูลเดิม (SQLite / mock)

สาเหตุ: ลง Prisma + SQL Server ไว้ข้าง store เดิม โดยไม่ได้ย้ายโค้ดที่อ่านข้อมูล

วิธีแก้: ตอบ Q0b = ย้าย แล้วทำ database-setup §4b · ถ้าเลือก "ทีหลัง" ต้องบอกชัดในสรุปว่าแอปยังรันบน store เดิม และบันทึกใน decisions.md (หรือ docs/adr/) + แถวใน board.md

มี login จริงแล้ว แต่คนยังเข้าแอปได้โดยไม่ต้อง login

สาเหตุ: login จำลองของ prototype (mock user, token ใน localStorage) ยังเป็นด่านที่ตัดสินจริง

วิธีแก้: ตอบ Q0c = ถอด → auth-setup §5.7 แทนที่ทุกจุดที่อ่าน user ปลอมด้วย session จริง แล้วลบด่านปลอมทิ้ง

บอกว่า "คง design เดิม" แต่หน้า login และ /admin/* ออกมาเป็นธีมม่วงคราม (indigo) ไม่เหมือนแอป

สาเหตุ: อ่าน "คง design เดิม" เป็น "ไม่ต้องทำ design" → ไม่ได้ scan → kit อยู่ที่ค่ากลางองค์กร

วิธีแก้: ส่ง preserve mode ให้ design-setup ทุกครั้ง: scan บังคับ, ข้อ 1 = โปรเจคเดิม, ข้อ 5 = shell เดิม, ข้อ 9 = ยึดของเดิม · auth ใช้ทาง merge (§5.6) ไม่ใช่ <AdminNav>

  • Preserve mode (§4b): ทำ inventory ของ store เดิม → map เป็น model ตามมาตรฐาน → เขียนใหม่หลัง signature เดิม (หน้าจอไม่ต้องแก้) → ตัดสินใจเรื่อง seed → ลบ store เดิม → บันทึกใน decisions.md

6กฎที่ห้ามพลาด

  • ตาราง PascalCase พหูพจน์ (LeaveRequests) · คอลัมน์ PascalCase · SP usp_* (ห้าม sp_) · function fn* · view vw* · ตาราง read-only จากระบบนอก ขึ้นต้น __EXT___
  • ใน Prisma: model camelCase + @@map("PascalCasePlural") และทุกฟิลด์มี @map("PascalCase")
  • ตาราง master/transaction ต้องมี Id, CreatedAt, UpdatedAt, CreatedBy, UpdatedBy, IsActive, IsDeleted · ลบแบบ soft delete (IsDeleted = 1) · ตัดคอลัมน์ได้เฉพาะเมื่อเขียนบรรทัด ⚠ deviation
  • ห้ามใช้ T-SQL reserved word เป็นชื่อคอลัมน์ — เติมคำขยาย เช่น key → SettingKey, group → GroupName, order → SortOrder
  • url อยู่ใน prisma.config.ts เท่านั้น · generator ต้องเป็น prisma-client-js · import type sql from 'mssql' เท่านั้น
  • ห้ามอ่าน process.env ตรง ๆ ในโค้ดแอป — ใช้ @/lib/env
  • รัน npx prisma generate หลัง migrate dev และหลังแก้ schema ทุกครั้ง
  • Raw SQL: sanitize ด้วย regex ก่อน แล้วค่อย parameterize เสมอ · เรียก SP แบบ $executeRaw`EXEC usp_Name ${p1}` · ห้าม $queryRawUnsafe / $executeRawUnsafe กับค่าจากผู้ใช้
  • ตาราง __EXT___ และทุกอย่างบน linked server = SELECT อย่างเดียว · ต้องการปรับค่า → สร้างตาราง override ฝั่งแอป
  • ตาราง auth 8 ตัว (User, Session, Account, Verification, RateLimit, Role, Permission, RolePermission) ใช้ชื่อเอกพจน์ — ยกเว้นตามไลบรารี ห้าม "แก้ให้ถูก"

  • โปรเจคใหม่ (scaffold เปล่า) → สัมภาษณ์เต็ม · โปรเจคเดิม (มี components.json, components/ui/, route จริง หรือใช้ MUI / Ant Design / Bootstrap ฯลฯ) → scan → ร่างข้อตกลงจากโค้ดจริง → ถามเฉพาะจุดขาด/ขัด
  • Preserve mode: scan บังคับ · ข้อ 1/5/9 ตอบให้ (โปรเจคเดิม · shell เดิม · ยึดของเดิม + rebase) · ถามข้อ 10 ฟ้อนต์ · ไม่ลง shell block ใหม่ (ยกเว้นครอบ <SidebarProvider> เปล่าให้ NavUser ของ auth) · ระดับคือ token + shell
  • Sync mode ("sync ข้อตกลง design" หลังอัปเดต plugin) → เทียบเวอร์ชันใน DESIGN.md กับ contract แล้วเสนอ diff ทีละเรื่อง บันทึกทุกการรับ/ไม่รับเป็นมติ — ไม่เขียน DESIGN.md ใหม่ทั้งไฟล์
  • Re-align mode ("ปรับให้ตรง org" บนโปรเจคที่เคยคงของเดิม) → scan ใหม่ ลิสต์ไฟล์ที่ token อย่างเดียวขยับไม่ได้ ถามครั้งเดียว แล้วต่อท้ายมติ ยึด org (re-align) ใน §10
  • ส่วนเสริมตามคำตอบ: next-themes (dark = มี) · exceljs (มี export) · npx shadcn@latest add chart (มีกราฟ) · @tiptap/* ^3 (มี rich text) · motion (custom motion = มี)
  • แถบ DEV ขึ้นเฉพาะ deploy ที่ basePath ลงท้าย -dev · deploy ไม่มี basePath = ไม่มีอะไรแยก dev/prod แถบจะไม่ขึ้นเลย
  • Windows: รันทุกคำสั่ง CLI/build จาก path สั้น (ห้ามใช้ subst)

6กฎที่ห้ามพลาด

  • ลำดับใช้ของ: primitive ของ shadcn → block/template → ประกอบเอง → custom ด้วย Tailwind utility เท่านั้น · ห้าม CSS ดิบ / inline style (ยกเว้นค่าที่เปลี่ยนตาม runtime)
  • ไอคอน lucide เท่านั้น ห้าม emoji · action เดียวกัน = ไอคอนเดียวกันทุกหน้า
  • ขนาด default ทุกที่ (หนึ่งแถว toolbar = หนึ่งขนาด) · size="cta" (44px มือถือ / 36px) เฉพาะ PageActions · PageFormActions · footer ของ dialog/sheet · size="icon" ได้เมื่อมี aria-label แต่ในแถวตารางต้องใช้ IconAction
  • สีปุ่มตัดสิน: บันทึก/ส่ง = primary · อนุมัติ = success เขียวทึบ · ปฏิเสธ = outline ขอบแดง + X · ยืนยันลบ = destructive แดงทึบ · ปุ่มรองในหัวหน้า = soft
  • ข้อมูลตาราง = DataTable เท่านั้น · ทุกตัวมี id ไม่ซ้ำ · ตัวกรองอยู่ใน toolbar ต่อจากช่องค้น · ข้อมูลแบบแบ่งหน้าฝั่ง server ต้อง sort/filter ฝั่ง server ผ่าน URL
  • วันที่/ตัวเลขผ่าน lib/format.ts เท่านั้น — จอแสดง DD/MM/YYYY ค.ศ. · ไฟล์ export ใช้ yyyy-MM-dd
  • สถานะ = สี + ไอคอน (StatusBadge) · คอนทราสต์ WCAG AA ≥ 4.5:1 ตรวจด้วย check-contrast.mjs ทุกครั้งที่แก้สี
  • ห้าม npx shadcn init เปล่า ๆ หรือ -b radix · ใช้ npx shadcn@latest init --preset b1ZzrZbs0 --pointer --yes · อ่าน API ของ component จาก registry ของ base-mira เท่านั้น (shadcn MCP ตอบเวอร์ชัน Radix)
  • ติดตั้ง shell block ก่อนแก้ button.tsx · ติด site-header ทุก shell แบบ sidebar · ปุ่มสลับที่ copy มาต้อง render ใน actions ของ site-header
  • ไฟล์ components/ui/ ที่มีอยู่แล้ว → diff แล้วถาม ห้ามทับเงียบ
  • DESIGN.md ชนะโค้ด และชนะตัวช่วยตกแต่ง (frontend-design, impeccable) — เสนอได้ แต่ทับไม่ได้

7อาการที่เจอบ่อย

บอก "ใช้ design เดิม" แล้วหน้า admin ออกมาเป็นอีก template หนึ่ง (สี indigo)

สาเหตุ: ข้ามการ scan → kit อยู่ที่ค่ากลางองค์กร

วิธีแก้: preserve mode = scan แล้ว rebase token ของ kit (primary, radius, ฟ้อนต์, สเกล control) ให้เท่าของเดิม · verify ✘ "Preserve mode honored" จนกว่าจะทำ

component ของ kit แสดงผลเพี้ยน ไม่มีสี ไม่มีขอบมน

สาเหตุ: โปรเจคยังเป็น Tailwind v3 (มี tailwind.config.* + @tailwind base) — ไฟล์ token เป็นแบบ v4 เท่านั้น

วิธีแก้: npx @tailwindcss/upgrade ก่อน shadcn init แล้วตรวจผล

shadcn init ล้มด้วย "No Tailwind CSS configuration found"

สาเหตุ: โปรเจคที่มาจากลำดับ database → design ยังไม่มี Tailwind

วิธีแก้: npm install -D tailwindcss @tailwindcss/postcss postcss + postcss.config.mjs + @import "tailwindcss"; ใน app/globals.css

ปุ่มหรือเมนูกดแล้วไม่มีอะไรเกิดขึ้น (เช่น "ปุ่ม logout กดไม่ได้")

สาเหตุ: โค้ดแบบ Radix (asChild, onSelect บน menu item, checked="indeterminate", delayDuration) — Base UI เมินเงียบ ๆ · มักมาจาก init เปล่า, -b radix หรือลอกโค้ดจาก shadcn MCP

วิธีแก้: ใช้ render={<X />}, onClick, indeterminate, delay · verify ✘ เมื่อเจอ Radix ใด ๆ ในโปรเจค

card และปุ่มทุกตัวกลายเป็นเหลี่ยม

สาเหตุ: ตอน merge token ลบทั้งบรรทัด --radius และสเกล calc() ของ preset แต่ไม่ได้ใส่สเกลตายตัวของ token file แทน — ไม่เหลือ radius เลย

วิธีแก้: ใช้ชุดของ globals.tokens.css ทั้งชุด (--radius: 0.75rem + --radius-sm/md/lg/xl… ค่าตายตัว lg = 0.45rem) แทนของ preset · verify ✘ จนกว่าจะครบ

การ์ดและปุ่มทั้งแอปโค้งเกินไป (การ์ด 12px)

สาเหตุ: คงสเกล calc(var(--radius) × …) ของ preset ไว้คู่กับ --radius: 0.75rem ของ token file — ทุกมุมโค้งขึ้น ×1.67

วิธีแก้: แทนที่สเกลของ preset ด้วยค่าตายตัวของ token file (มติ 2026-10-16 TK-RAD) · verify ✘ เมื่อเจอคู่นี้

แอปไม่ขึ้นทั้งแอป — t() / getLocale() โยน error ตอน render

สาเหตุ: ไม่ได้ลงทะเบียน createNextIntlPlugin('./i18n/request.ts') ใน next.config.ts

วิธีแก้: เพิ่ม plugin โดยระบุ path ชัด ๆ แล้ว export withNextIntl(nextConfig)

หน้าที่มี tooltip ของ sidebar crash ตอน prerender

สาเหตุ: ไม่มี TooltipProvider ครอบ root layout (Tooltip ของ mira ไม่ครอบ provider ให้เอง)

วิธีแก้: ลำดับ provider: NextIntlClientProvider (นอกสุด) → QueryProvider → ThemeProvider → TooltipProvider → children + <Toaster richColors />

Jenkins stage Build พัง Cannot read properties of undefined (reading 'endsWith') ที่ app/layout.tsx

สาเหตุ: ตัด ?? '' ออกจาก isDevEnvironment() — ตอน CI ตั้ง SKIP_ENV_VALIDATION ค่าเป็น undefined

วิธีแก้: คง ?? '' ไว้ตาม asset

ผู้ใช้แยกไม่ออกว่าอยู่ dev หรือ prod (หน้า login ไม่มีแถบเตือน)

สาเหตุ: พึ่งป้าย DEV เล็ก ๆ ใน site-header อย่างเดียว ซึ่งหน้า login ไม่มี

วิธีแก้: ใน app/layout.tsx render {isDevEnvironment() && <DevEnvironmentBar />} เป็นลูกคนแรก และ title ขึ้นต้น [DEV] · lib/env.ts ต้องมี NEXT_PUBLIC_BASE_PATH ทั้งใน client และ runtimeEnv

บางหน้าไม่มี [DEV] นำหน้าชื่อแท็บ

สาเหตุ: หน้านั้นตั้ง title เองทับของ root

วิธีแก้: ใช้ title: { template: `${DEV_PREFIX}%s · <App name>`, default: … } · โปรเจคที่ลงรุ่น 4.71.0–4.75.0 (ต่อท้าย (DEV)) ให้เปลี่ยนเป็นขึ้นต้น

เพิ่ม shell block แล้ว variant ที่เพิ่งใส่ใน button.tsx หายไป

สาเหตุ: add <block> ถามทับไฟล์ทีละไฟล์ (แม้ใส่ --yes) ตอบ y แล้วทับ

วิธีแก้: ลง block ก่อนแก้ button.tsx · รันแบบไม่มีคนตอบ ใช้ yes n | นำหน้า

build พังที่ date picker

สาเหตุ: button.tsx จาก registry ไม่มี variant field ที่ date picker ใช้

วิธีแก้: แก้ button.tsx ตาม assets/ui/button-variants.md — field (บังคับ) · success (อนุมัติ) · แทน destructive ด้วยแดงทึบ · soft · soft-* · size cta (verify ✘ เมื่อไม่มี success/field · เตือนเมื่อไม่มี soft/cta/แดงทึบ)

Select ในฟอร์มหดเหลือกว้างเท่าค่าที่เลือก

สาเหตุ: SelectTrigger ของ base-mira เป็น w-fit

แถบด้านบนมีแค่ปุ่มย่อ sidebar ดูเหมือน "หน้าเปล่า ๆ"

วิธีแก้: วางเป็นลูกคนแรกของ SidebarInset ส่งรายการเมนูชุดเดียวกับ sidebar ให้

copy ปุ่มสลับธีม/ภาษามาแล้ว แต่ไม่เห็นบนจอ

สาเหตุ: copy ไฟล์แต่ไม่ได้ render

วิธีแก้: ใส่ <LanguageSwitcher /> (th+en) แล้ว <ThemeToggle /> (dark = มี) ใน actions ของ site-header

โลโก้บน sidebar เป็นสีดำ แทบมองไม่เห็น

สาเหตุ: ใช้ <img> กับ SVG ที่เป็น fill="currentColor" — รูปไม่รับสีจาก CSS

เส้นคั่นข้างปุ่มย่อ sidebar ชิดขอบบน ไม่อยู่กลาง

สาเหตุ: separator แนวตั้งได้ self-stretch ทับ items-center

วิธีแก้: ใช้ h-4 คู่กับ data-vertical:self-center

breadcrumb ตัวแรกเป็นชื่อหน้าอื่น เช่น "ภาพรวม › ใบลา"

สาเหตุ: สร้าง crumb เอง ไม่ได้ใช้หัว group ของเมนู

วิธีแก้: ให้ฟิลด์ group ของทุก item เป็นข้อความหัวข้อจริงของ sidebar · ใช้ deriveCrumbs ของ site-header

เมนูยาวเกินจอ แต่ไม่มีอะไรบอกว่าเลื่อนลงได้

สาเหตุ: SidebarInset เป็น flex item ที่ min-width: auto

วิธีแก้: scaffold และรันทุกคำสั่งที่ path สั้นจริง แล้วค่อยย้ายโปรเจค · junction ไม่ช่วย · ห้าม subst

ปรับให้ตรง org แล้ว หน้าเดิมยังสีเก่า กลายเป็นสอง template ในแอปเดียว

6กฎที่ห้ามพลาด

  • Keycloak กลางตัวเดียว แต่ หนึ่งโปรเจค = หนึ่ง client (Client ID = ชื่อโปรเจค) · OIDC Authorization Code + PKCE (S256) เท่านั้น
  • ชื่อ cookie ต้องมี prefix จาก basePath และต้องตรงกันใน lib/auth.ts, proxy.ts, lib/actions/auth.ts · BETTER_AUTH_URL บังคับ (z.url()) ทุก environment
  • ลำดับ guard ของทุก mutation: session → permission → action → audit log · guard ใน UI อย่างเดียวไม่พอ
  • Permission ≠ scope: route ที่รับ empCode/owner id จากฝั่ง client ต้องเช็ค lib/scope.ts และตอบ 404 เมื่อไม่อยู่ในขอบเขต
  • ไม่มีการสมัครเอง (disableSignUp: true) · ไม่สร้างบัญชี SSO/LDAP ล่วงหน้า · ตั้ง role ล่วงหน้าได้ โดยผูกกับ EmpCode/AD login (ไม่ใช่อีเมล)
  • อีเมลโดเมนองค์กรเป็นของ SSO/LDAP — สร้างบัญชี Local บนโดเมนเหล่านั้นไม่ได้
  • [Local] นโยบายรหัสผ่านอยู่ใน lib/password-policy.ts ไฟล์เดียว · ลิงก์ reset ใช้ได้ครั้งเดียว 1 ชั่วโมง · ตอบเหมือนกันไม่ว่าอีเมลมีจริงหรือไม่ · เปลี่ยนรหัสแล้วตัด session อื่นทิ้ง · เปลี่ยนรหัสเองต้องใส่รหัสเดิม
  • Audit log ทุก event ของ auth และทุก mutation ที่มีสิทธิ์พิเศษ — ห้ามทำให้ login พัง · ชื่อ action มาจาก AUDIT_ACTIONS เท่านั้น · ห้าม UPDATE/DELETE ActivityLogs
  • Logout ใช้ <form action={logoutAction}> (SSO ใช้ ssoLogoutAction) ห้าม signOut() จาก auth-client
  • UI ใช้ API ของ Base UI (render, onClick) · ลบด้วย ConfirmActionDialog ไม่ใช่ window.confirm
  • admin สร้างผู้ใช้ด้วย hashPassword (better-auth/crypto) ไม่ใช่ auth.api.signUpEmail
  • หลัง bump better-auth ทุกครั้ง (รวม patch) เทียบ node_modules/better-auth/dist/plugins/*/schema.mjs กับ prisma/schema.prisma แล้ว migrate ส่วนต่าง
  • บันทึกบรรทัด ⚠ deviation ของตาราง auth (ไม่มี audit columns + ลบจริง) ระหว่างติดตั้ง

7อาการที่เจอบ่อย

ERR_TOO_MANY_REDIRECTS หลัง deploy ใต้โดเมนกลาง (สองแอปบนโดเมนเดียว)

สาเหตุ: cookie ชื่อเดียวกันที่ path=/ — แอป B ได้ cookie ของแอป A ไป

วิธีแก้: advanced.cookiePrefix จาก basePath และใช้ prefix เดียวกันใน proxy.ts + actions

ERR_TOO_MANY_REDIRECTS วน / ↔ /login เฉพาะ browser เดียว (browser ใหม่ใช้ได้)

สาเหตุ: มี cookie เก่า/หมดอายุ — proxy.ts รุ่นเก่าเด้งตามการมี cookie แต่ layout เช็ค session จริงแล้วไม่เจอ

วิธีแก้: ใช้ proxy.ts 4.74.0 ขึ้นไป (sync ด้วย kit-sync) และให้หน้า login เช็ค auth.api.getSession() เองก่อน redirect('/')

login ในเครื่องได้ แต่บน production วนไม่จบ

สาเหตุ: บน https cookie ได้ชื่อ __Secure- แต่การตั้งค่าไม่ตรงกับ URL จริง (หรือ BETTER_AUTH_URL ว่าง แล้วไปเดาจาก NODE_ENV)

วิธีแก้: ตั้ง BETTER_AUTH_URL ให้ตรงกับที่ผู้ใช้เข้าจริงในทุก environment แล้วใช้สูตรตั้งชื่อ cookie ตัวเดียวกันทุกไฟล์

ทุกหน้าเด้งกลับ /login หลัง login ด้วย LDAP

สาเหตุ: ชื่อ cookie ผิด (ขาด __Secure- หรือ prefix ของแอป) หรือ token ไม่ได้ sign

วิธีแก้: ใช้ SESSION_COOKIE_NAME ตามสูตร + signSessionToken()

กด logout บน https แล้วยังอยู่ในระบบ

สาเหตุ: cookieStore.delete() ไม่ใส่ Secure — ลบด้วยชื่อ/flag ต่างจากตอนตั้ง

วิธีแก้: set(name, '', { maxAge: 0, secure: true })

login แบบ Local แล้วเจอหน้า 404

สาเหตุ: ค่า cookie ถูก URL-encode ซ้ำสองชั้น

วิธีแก้: decodeURIComponent ก่อน cookieStore.set

logout แล้ว session ใน database ไม่ถูกลบ

สาเหตุ: ลบด้วย token ที่ sign แล้ว แต่ DB เก็บ token ดิบ

วิธีแก้: ตัดลายเซ็นออกด้วย lastIndexOf('.') ก่อนลบ

ไฟล์ static ขึ้น Unexpected token '<' ใน console

สาเหตุ: guard ใน proxy.ts จับ _next/static แล้วส่งหน้า login กลับไป

วิธีแก้: คง early return ของ /_next/ (และ /api/health) ไว้

auth-client เรียก …/get-session แล้ว 404

สาเหตุ: ส่ง baseURL ที่มี path ให้ createAuthClient

วิธีแก้: ไม่ใส่ baseURL · ใช้ basePath: `${BASE_PATH}/api/auth`

NEXT_PUBLIC_BASE_PATH ว่างใน bundle ฝั่ง browser

สาเหตุ: อ่านผ่าน wrapper ของ createEnv() ซึ่งว่างใน client bundle ภายใต้ Turbopack

วิธีแก้: ไฟล์ฝั่ง client อ่าน process.env.NEXT_PUBLIC_BASE_PATH ตรง ๆ · ไฟล์ฝั่ง server ใช้ @/lib/env (ต้องประกาศทั้งใน client และ runtimeEnv)

ลิงก์รีเซ็ตรหัสผ่านในอีเมลเปิดแล้ว 404 (เฉพาะ production)

สาเหตุ: URL ที่ Better Auth สร้างไม่มี basePath

วิธีแก้: สร้างลิงก์เองจาก token: ${env.BETTER_AUTH_URL}${env.NEXT_PUBLIC_BASE_PATH}/reset-password?token=… · หน้า /reset-password ต้องเป็น public

ปุ่ม "ลืมรหัสผ่าน" ตอบ RESET_PASSWORD_DISABLED ฟอร์มใช้ไม่ได้

สาเหตุ: ติดตั้งปุ่มโดยไม่มี sendResetPassword (ยังไม่มี mail)

วิธีแก้: ห้ามใส่ปุ่มถ้ายังไม่มี mail — ติดตั้ง mail-setup แล้วกลับมาเติมทั้งชุดตาม §5.5

6กฎที่ห้ามพลาด

  • sendTemplatedMail คือทางเข้าเดียวของเมล workflow · ห้ามสร้าง transport ใหม่รายจุด
  • ทุกครั้งต้องส่ง actor (email + hasDevMode)

5ตัวเลือก / เงื่อนไข

  • Virus scan [SCAN] (opt-in): ทำตามทุก marker — copy lib/virus-scan.ts, ใส่บล็อก scan กลับใน route อัปโหลด (scanStatus = 'clean'), ด่านดาวน์โหลดเป็น !== 'clean', env CLAMAV_*, service clamav + clamav-db, pingScanner() ใน /api/health · ไม่เปิด = แถวเก็บเป็น 'unscanned' และด่านเป็น === 'infected'
  • การผูกไฟล์กับ record: A polymorphic (entityType + entityId — ที่ skeleton ให้มา) เหมาะเมื่อหลายชนิดและเพิ่มเรื่อย ๆ แต่เกิดแถวกำพร้า · B FK จริงต่อชนิด เหมาะเมื่อ 1–2 ชนิดและห้ามมีกำพร้า · C คอลัมน์บนตารางธุรกิจ เมื่อมีไฟล์เดียวต่อ record ตลอดไป · ผสมได้
  • Retention sweep [SWEEP]: host cron → POST /api/cron/attachments-sweep ทำงานซ้ำได้ปลอดภัย · RETENTION_DAYS < 7 ถูกปฏิเสธในโค้ด · OWNERS ใส่หนึ่งรายการต่อ entityType ของ pattern A/C · ทดลองก่อนด้วย ?dryRun=1
  • [SWEEP] ต้องมี CRON_SECRET — ถ้า cicd-setup ยังไม่ได้เพิ่ม ให้ทำขั้น [CRON] ของ cicd ตอนนี้

6กฎที่ห้ามพลาด

  • ไฟล์อยู่บน Docker volume เท่านั้น — ไม่ใช่ใน container, ไม่ใช่ public/, ไม่ใช่ใน DB · bind mount ใต้ /home/docker02/appdata ห้าม named volume
  • แถวใน DB คือความจริง · path สร้างเองเสมอ ห้ามใช้ชื่อไฟล์ของผู้ใช้เป็นส่วนของ path
  • ลำดับด่านดาวน์โหลด: session → permission → scope ราย record → scanStatus → stream → audit log · ไม่มีไฟล์และไม่มีสิทธิ์ตอบ 404 ทั้งคู่
  • ส่งไฟล์เป็น application/octet-stream + Content-Disposition: attachment + nosniff เสมอ
  • อัปโหลดผ่าน Route Handler ไม่ใช่ Server Action
  • [SCAN] สแกนในหน่วยความจำก่อนเขียนลงดิสก์ · สแกนเนอร์ล่ม/timeout/ตอบไม่ชัด = ปฏิเสธ (503)
  • ลบแบบ soft delete (IsDeleted = 1) — ไฟล์จริงถูกลบโดย sweep หลังครบระยะ
  • เขียน canReadAttachment จากตัวตนใน session — ห้ามทิ้งโครงที่ปฏิเสธทุกอย่างไว้ หรือใช้ !canSeeAll

dates-timezones.md — วันที่และเขตเวลา

หลักเดียว: รู้ว่า Date แต่ละตัวยึดอะไร (UTC-midnight, local-midnight หรือเวลาจริง) แล้วอ่าน/แปลง/ผูก DB ให้ตรงกัน

วันที่เลื่อน −1 วัน (เฉพาะกลางคืน หรือเฉพาะบน server) — กะ OT/เข้างานอ่านผิดวัน

สาเหตุ: ส่ง JS Date เข้า $queryRaw/stored procedure — driver @prisma/adapter-mssql ผูกเป็น UTC · 2026-06-03 00:00 +07:00 ไปถึงเป็น 2026-06-02T17:00Z แล้ว SQL อ่านเป็นวันก่อนหน้า ไม่มี error
วิธีแก้: ผูกเป็น string จาก getter แบบ local

// ❌ เลื่อน −7 ชม. บน server UTC+7
await prisma.$queryRaw`EXEC usp_GetShiftSchedule ${startOfDay(date)}, ${empCode}`;
// ✅
await prisma.$queryRaw`EXEC usp_GetShiftSchedule ${toLocalYmd(date)}, ${empCode}`;
  • toLocalYmd(d) มีตัวเดียวใน lib/utils.ts — ห้ามสร้างตัวที่สองใน service
  • startOfDay(date) ยังคืน Date จึงยังเลื่อน — ต้องแปลงเป็น string
  • ตอนแก้ ให้ grep ทุก $queryRaw/EXEC ที่กรองด้วยวันที่ แล้วแก้ทั้งชุด (เคยกลับมาซ้ำสองรอบเพราะแก้แค่จุดที่ถูกแจ้ง)
  • ตาราง Prisma ของแอปเองไม่ต้องแก้ — เขียนและอ่านเลื่อนเท่ากันจึงหักล้างกัน
  • เทสต์ที่ mock $queryRaw จับไม่ได้ — ให้ assert ค่าที่ผูก: expect(queryRaw.mock.calls[0][2]).toMatch(/^\d{4}-\d{2}-\d{2}$/)
ปุ่มเลือกวันที่ขึ้นวันก่อนหน้า แต่ค่าที่บันทึกและตารางถูก

สาเหตุ: ใช้ formatDate(Date) (อ่าน UTC) กับ Date จาก calendar cell ซึ่งเป็น local-midnight — บน browser UTC+7 จะช้าไปหนึ่งวัน (เคยเจอ: ค่า 2026-10-08 ปุ่มโชว์ 07/10/2026)
วิธีแก้: แปลงผ่าน toDateKey(date) ก่อน หรือ formatDate(toDateKey(date)) สำหรับ label

อ่านวันที่ผิดเพราะใช้ getter ไม่ตรงกับที่มาของ Date
Date มาจากยึดอ่านด้วย
คอลัมน์ SQL DATE ผ่าน PrismaUTC-midnightgetUTCFullYear/Month/Date, toISOString().slice(0, 10)
SQL TIME(0) ผ่าน driver mssqlเวลาบนนาฬิกาเก็บในส่วน UTCgetUTCHours/getUTCMinutes ผ่าน formatter กลางตัวเดียว

หน้า detail ไม่มีวันตรงกับหน้า summary

สาเหตุ: ฝั่งหนึ่งเขียนด้วย string ดิบ อีกฝั่งกรองด้วย .toISOString()
วิธีแก้: เทียบข้ามฝั่ง (JS date-key ↔ SQL DATE) ต้องยึดแบบเดียวกัน และค่าที่ฝั่งหนึ่งเขียนกับอีกฝั่งกรองต้อง serialize ด้วย helper ตัวเดียวกัน

วันถูกตอนกลางวัน แต่ช้าไปหนึ่งวันสำหรับแถวที่สร้างช่วง 00:00–06:59

สาเหตุ: ใช้ formatter แบบ UTC กับค่าที่เป็นเวลาจริง
วิธีแก้: แยก column ก่อนเลือก formatter

  • formatDate — อ่านส่วน UTC สำหรับวันบนปฏิทิน (Prisma @db.Date, วันลา, วันหยุด)
  • formatDateTime — อ่านเวลา local + HH:MM สำหรับเวลาจริง (createdAt, updatedAt, submittedAt)
  • เขียนเวลาบนนาฬิกากลับ: ประกอบด้วย Date.UTC(y, m - 1, d, hh, mm) · ใช้ <input type="time"> + ช่องวันแยก ดีกว่า datetime-local
ปีบนจอเพี้ยนไป ~543 (เป็น พ.ศ.)

สาเหตุ: มี +543 หลงอยู่ หรือเรียก Intl ด้วย locale th-TH เปล่า ๆ (หรือ toLocaleDateString('th-TH'))
วิธีแก้: มติองค์กร 2026-08-24: เก็บ ค.ศ. แสดง ค.ศ. — ไม่มีทางแปลง พ.ศ. ใด ๆ

  • ห้าม ±543 ทุกที่ ไม่มีข้อยกเว้น (verify.mjs กฎ BE-YEAR fail ทันที)
  • ปีทุกตัวบนจอผ่าน lib/format.ts ซึ่งใช้ th-TH-u-ca-gregory และ en-GB สำหรับ DD/MM/YYYY
  • จับคู่วันหยุดด้วยวันที่ (holidayDate) ไม่ใช่คอลัมน์ปี
loop วันที่ไม่จบ (เทสต์ค้าง ~18 นาที ได้ผลรวมขยะ)

สาเหตุ: ขอบเขตของ loop เป็น object เดียวกับ cursor เช่น const end = cond ? cur : other — ขอบเลื่อนตาม cursor

  • บั๊กนี้เกิดได้แม้มีศูนย์แถว — เปิดหน้าแล้วดู console ไม่ต้องไล่ในข้อมูล
